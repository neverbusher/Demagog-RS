# Открытые проблемы Demagog-RS

Дата проверки: 2026-10-22. Контекст: после аудита кода и UI, релиз 0.1.7. В `main` лежат невыпущенные исправления аудита; `main` опережает тег `v0.1.7`.

## Исправлено локально (не запушено)

- **P-01. Правка во время обработки.** Коммит `494190f`: редакторы и мутирующие кнопки блокируются на время обработки, snapshot исходника страхует от изменений и помечает результат устаревшим.
- **P-02. Чанки пустого результата.** Коммит `2e5c08f`: пустой результат очищает чанки, экспорт блокируется и пересобирает устаревшие чанки перед записью.
- **P-03. Порядок EPUB.** Коммит `9f3dc0b`: чтение через `container.xml` → OPF → spine, ошибки глав возвращаются вместо молчаливого пропуска; есть интеграционные тесты на ZIP.
- **P-05. Клонирование результата.** Коммит `856f2f4`: пайплайн отдаёт результат вызывающему потоку, `Completed` отправляется без полного clone.
- **P-07. Параллельные векторы.** Коммит `f734af8`: метаданные и процессор объединены в `LoadedDictionary`; рассинхронизация невозможна по конструкции.
- **P-09. CI.** Коммит `d77ef3e`: добавлены `cargo fmt --check` и `cargo clippy -- -D warnings` для обоих бэкендов.
- **P-10. Лимиты архивов.** Коммит `d12db05`: ограничены размер записи (256 МБ) и суммарный размер глав EPUB (512 МБ); есть тест на лимит.
- **P-11. Метаданные книги.** Коммит `8d6fe5f`: названия из FB2 `book-title`, EPUB `dc:title` и DOCX `core.xml`; сохранение исходника запоминает путь.
- **P-12. Тема.** Коммит `6b6b085`: одно поле `theme: ThemeMode` с миграцией старых `dark_mode`/`warm_mode`.
- **P-13. Настройки.** Коммит `1ad1e38`: повреждённый `settings.json` даёт предупреждение в приложении и резервную копию.
- **P-08. UI-тесты.** Коммит `4499889`: добавлен `egui_kittest`; покрыты disabled-редакторы во время обработки, экспорт пустого результата и пересборка устаревших чанков через UI. Это база для безопасного разбора P-06.
- **P-06. Монолит UI.** Коммит `664bb7c`: `app.rs` разделён на `app/mod.rs`, `app/views.rs` и `app/tests.rs`; `update_ui` сокращён с ~1,1 тыс. строк до навигации по секциям, вкладки вынесены в отдельные методы.

## P3 — UX, процесс и мелкие долги

### P-14. Нативные подтверждения не следуют тёмной теме

**Статус:** известное ограничение, подтверждено.

**Где:** `confirm_destructive`, `rfd::MessageDialog`.

**Сейчас:** используется современный TaskDialog, но Win32 не наследует кастомную тему приложения; окно остаётся светлым. Ограничение описано в CHANGELOG 0.1.7.

**Последствия:** визуальный разрыв при работе в тёмной или тёплой теме. Это платформенное ограничение, не баг приложения.

### P-15. Иконка окна: утечка HICON и повторные попытки

**Статус:** известное ограничение, подтверждено.

**Где:** `apply_window_icon` в `src/ui/window.rs`, вызов из `update_ui`.

**Сейчас:** HICON намеренно живёт до конца процесса; при неудаче иконка пытается примениться каждый кадр без ограничения попыток.

**Последствия:** небольшая одноразовая утечка на процесс и лишние обходы окон, если применить иконку не удалось. Влияние низкое.

### P-16. Сценарий использования чанков всё ещё не подтверждён

**Статус:** продуктовый вопрос, не техническая ошибка.

**Где:** вкладка «Чанки», экспорт JSON, настройки нарезки.

**Сейчас:** Drama3-нейминг убран, чанки работают и синхронизируются с правками, но продуктовый сценарий (кому и зачем нужен этот экспорт) не подтверждён.

**Последствия:** поддержка функции может стоить больше, чем приносит пользы; вопрос стоит решить до дальнейшего развития вкладки.

### P-17. Версия и релизный процесс расходятся с `main`

**Статус:** подтверждено.

**Где:** `Cargo.toml`, `CHANGELOG.md`, `dist/`, root-exe.

**Сейчас:** `main` опережает тег `v0.1.7`; версия в `Cargo.toml` и локальных exe — 0.1.7; тег `v0.1.7` указывает на более ранний коммит без аудита.

**Последствия:** непонятно, какой именно код соответствует релизу; для публикации нужно поднять версию, обновить CHANGELOG и пересобрать пакет.
