# Книгорез — дизайн

Дата: 2026-11-19. Статус: согласован в диалоге, ожидает вычитки.

## Цель

Перенести в Demagog-RS функционал нарезки книги на части из Балаболки («Сервис | Разбить файл на части» + деление по оглавлению из «Разделить и преобразовать в аудиофайлы») в виде отдельной вкладки «Книгорез». Только текст: аудио-возможности Балаболки не переносим — приложение готовит книги к озвучке, а не озвучивает.

## Источник функционала (что выяснено по установке Балаболки)

- Диалог «Разбить файл на части»: способы деления — независимые чекбоксы (`Splitter_SplitBySize/ByKeywords/ByEmptyLines/ByAllCapital/ByContents` в `%APPDATA%/Balabolka/balabolka.cfg`), несколько могут быть включены одновременно. Дефолты: размер 10 000 символов, стартовый номер 1, номер после имени, UTF-8, `RemoveKeyword=Off`, `CreateSubfolder=Off`.
- Движок (документация BLB2TXT): `-c` извлекает позиции начал глав из структуры электронной книги; `%Header%` — заголовок из оглавления; `-m`/`-j` — минимальный размер части / игнорирование границы главы, если предыдущая часть меньше N символов; размер считается в символах включая пробелы и переводы строк.
- Шаблоны имён: `%Number%`, `%FileName%`, `%FirstLine%`, `%Header%`; без `%Number%` номер добавляется до/после имени. Запрещённые символы шаблона: `/ \ ? * : " < > |`.
- Кнопка «Тест» показывает количество частей до реальной записи.

## Принятые решения

1. Источник текста — **исходный текст** открытого документа (`BookDocument.raw_text`), без словарей и ударений.
2. Методы: размер, ключевые слова, две пустые строки, ЗАГЛАВНЫЕ строки, оглавление (FB2/EPUB). Чекбоксы, комбинируются.
3. Экспорт — только TXT на часть.
4. Охват — только текущий документ; пакетное деление — позже.
5. Сверх GUI-паритета: минимальный размер части (аналог `-m`/`-j`) и подпапка с именем книги.

## Архитектура

Подход A: отдельный чистый сервис + книжный читатель отдаёт заголовки. Существующий chunker («Чанки») не меняет поведения — только видимость helpers.

### Домен (`src/domain/mod.rs`)

```rust
pub struct BookHeading { pub offset: usize, pub title: String }
```
`offset` — байтовое смещение начала части в `raw_text`; `title` — текст заголовка (первая непустая строка блока заголовка).

`BookDocument` получает поле `headings: Vec<BookHeading>` (у TXT/DOCX — пустое). Обновляются все конструкторы: 4 читателя, пример в `ui/app/mod.rs`, 3 места в тестах.

```rust
pub struct SplitConfig {
    pub by_size: bool,            // default true
    pub max_chars: usize,         // default 10_000, диапазон 1_000..=500_000
    pub by_keywords: bool,        // default true
    pub keywords: String,         // default "Глава, Часть, Пролог, Эпилог"
    pub by_blank_lines: bool,     // default false
    pub by_all_caps: bool,        // default false
    pub by_toc: bool,             // default false
    pub min_chars: usize,         // default 0 = выключено
    pub remove_heading: bool,     // default false
    pub template: String,         // default "%Number% %FirstLine%"
    pub add_number: bool,         // default true
    pub start_number: usize,      // default 1, минимум 1
    pub output_dir: Option<PathBuf>, // default None
    pub subfolder: bool,          // default false
    pub overwrite: bool,          // default true
}
```

`AppSettings` получает `#[serde(default)] pub split: SplitConfig`.

### Читатель (`src/io/book_reader.rs`)

- **FB2**: `extract_xml_paragraphs` дополнительно собирает заголовки. Отслеживаем глубину `<section>`; при старте `<title>` внутри секции (в body, вне skip-тегов) запоминаем смещение = текущая длина `out` после добавления разделительного `\n`; при закрытии `</title>` берём добавленный подстрок, первая непустая строка (trimmed) — заголовок. Пустые заголовки не добавляем. Финальный `out.trim()` сдвигает смещения — компенсируем на величину ведущего trim. Секции bodies с примечаниями учитываются (их текст и так попадает в raw_text). Заголовки из `<description>` не попадают (skip-теги).
- **EPUB**: граница = каждый непустой документ spine. Перед добавлением части фиксируем смещение (длина `full_text` + 2 на разделитель `\n\n`, если не первая) и заголовок = первая непустая строка части.
- **TXT/DOCX**: `headings` пуст.

### Сервис (`src/services/book_splitter.rs`, новый)

Чистая функция:

```rust
pub struct BookPart { pub title: Option<String>, pub text: String }
pub fn split_book(text: &str, headings: &[BookHeading], config: &SplitConfig) -> Vec<BookPart>
```

Порядок операций:

1. **Сбор структурных границ** (смещения в `raw_text`) со всех включённых методов, сортировка и дедупликация:
   - *Ключевые слова*: список парсится по запятой, элементы trim, пустые отбрасываются. Граница — строка, чей trimmed-вариант начинается с любого ключевого слова, **без учёта регистра** (Unicode lowercase). Заголовок границы = эта строка.
   - *ЗАГЛАВНЫЕ*: строка содержит ≥ 1 букву с регистром и все её буквы — заглавные (цифры, пунктуация, пробелы допускаются). Заголовок = строка.
   - *Две пустые строки*: ≥ 2 подряд пустые (whitespace-only) строки; граница = первая непустая строка после них. Заголовка нет.
   - *Оглавление*: границы из `headings`, заголовок = `heading.title`.
   - При совпадении смещений приоритет заголовка: оглавление > строка границы > нет.
   - Текст до первой границы — часть-преамбула (`title = None`).
2. **Формирование частей**: текст между границами, trimmed; пустые части отбрасываются. Если `remove_heading` и у границы есть заголовок-строка — первая строка части удаляется (у многострочного FB2-title удаляется только первая строка). Часть, опустевшая после удаления, отбрасывается.
3. **Слияние по минимальному размеру**: если `min_chars > 0`, граница игнорируется, пока накопленная часть меньше `min_chars` (аналог `-j`: следующая глава присоединяется к предыдущей маленькой части).
4. **Size-cap**: если `by_size`, каждая часть длиннее `max_chars` дополнительно режется по абзацам (строкам); слишком длинный абзац — по предложениям, слишком длинное предложение — по словам/символам. Helpers `split_into_sentences`/`split_long_sentence` из `chunker.rs` становятся `pub(crate)` и переиспользуются. Первая под-часть наследует `title`, остальные `title = None`. Если включён только размер — это чистая нарезка по размеру.
5. Пустой текст → пустой список частей. Ни одного включённого метода → одна часть со всем текстом (UI не даёт экспортировать без методов).

### Именование файлов

- Переменные: `%Number%` — порядковый номер с ведущими нулями до ширины `max(2, цифры(start_number + N - 1))`; `%FirstLine%` — первая непустая строка текста части, trimmed, обрезка до 60 символов; `%FileName%` — stem исходного файла, иначе `document.title`; `%Header%` — `title` части, иначе первая строка. Неизвестные `%…%` остаются как есть.
- `add_number = true` и в шаблоне нет `%Number%` → номер добавляется в конец через пробел. `add_number = false` → номер не добавляется.
- Пустой шаблон → дефолтный.
- Санитизация rendered-имени: `/ \ ? * : " < > |` и управляющие символы → `_`; схлопывание пробелов; trim; удаление хвостовых точек/пробелов; обрезка до 120 символов; пустое → «часть». Затем `.txt`.
- Коллизии: переиспользуем `unique_target` из `services/batch.rs` (становится `pub(crate)`): суффикс « (2)», « (3)»; ключи дедупликации нормализуются к нижнему регистру (Windows-FS регистронезависима). Семантика как в пакете: `overwrite = true` — перезапись, но коллизии внутри одного запуска всё равно получают суффикс; `overwrite = false` — существующие файлы сохраняются, новые получают суффикс.

### Экспорт

- Части пересчитываются заново перед записью (превью может устареть).
- Папка создаётся (`create_dir_all`); при `subfolder` — подпапка с санитизированным именем книги.
- Кодировка UTF-8 без BOM, как пакетный экспорт.
- Частей > 200 → диалог подтверждения.
- Запись синхронная; ошибки по файлам собираются, не прерывают остальные; итог в статусе: «Сохранено N частей в <папка>» + список ошибок.

### UI (`src/ui/app/splitter.rs`, новый; вкладка в `views.rs`/`mod.rs`)

- `ActiveTab::BookCutter`, кнопка вкладки «🔪 Книгорез» между «Чанки» и «Журнал замен».
- Панель настроек: чекбоксы методов; поле размера (видно при `by_size`); поле ключевых слов (видно при `by_keywords`); минимальный размер; «удалять строку-заголовок»; шаблон + живой пример рендера первой части; стартовый номер; «добавлять номер»; папка назначения («📂 Выбрать…», rfd); «подпапка с именем книги»; «перезаписывать».
- «🔍 Тест» — считает превью: строка «Частей: N» (при N ≤ 1 предупреждение «текст не разделился — проверьте методы/ключевые слова»), список частей: сворачиваемый заголовок «имя файла — M симв.», внутри полный текст части (monospace, selectable, editor font). При изменении настроек или исходного текста превью помечается устаревшим. При первом открытии вкладки с непустым документом тест выполняется автоматически.
- «💾 Нарезать» — экспорт. Неактивна: нет методов, пустой документ, не выбрана папка, идёт обработка (`is_busy`).
- Пустой документ → подсказка открыть книгу.
- «Оглавление» неактивен с подсказкой «доступно для FB2/EPUB», если `headings` пуст.
- Ключевые слова включены, но список пуст → ошибка-подсказка при Тесте/экспорте.

### Персистентность

`SplitConfig` целиком в `settings.json`, сохранение при изменении (`save_settings`, как чанки/пакет). Состояние превью не сохраняется.

## Тестирование

- Юнит-тесты `book_splitter`: каждый метод (регистронезависимость и начало строки у ключевых слов, преамбула, удаление заголовка, капс с цифрами, две пустые строки, границы оглавления), объединение границ, слияние по мин. размеру, size-cap по абзацам и длинным предложениям, пустой текст, шаблон (переменные, padding, санитизация, коллизии, номер без `%Number%`).
- Тесты читателя: FB2-фикстура с секциями (смещения и заголовки, компенсация trim), EPUB из двух spine-документов (2 заголовка со смещениями), TXT — пустой `headings`.
- Существующие 178 тестов и golden 22/22 остаются зелёными; конструкторы `BookDocument` в тестах обновляются.
- UI — живая проверка: открыть FB2, нарезать по оглавлению, экспортировать, сверить файлы на диске.

## Вне скоупа

Аудио целиком (паузы, плейлисты, «произносить номер блока», единый файл с главами); пакетное деление очереди; структура DOCX/TXT; выбор кодировки; вставка текста перед заголовками (`-hh`); авто-генерация оглавления (`-toc`); регистрозависимый режим ключевых слов; именованные закладки.
